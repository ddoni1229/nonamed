nonamed 배포 가이드

GitHub Pages(화면) + Supabase(데이터·로그인)로 실제 서비스를 여는 순서입니다. 한 단계씩 진행합니다.

전체 순서

  1. 1

    GitHub Pages에 올리기

    인터넷 주소가 생깁니다. 이 단계에서는 데이터가 아직 각자 브라우저에만 저장됩니다.

    완료 후 주소 알려주기
  2. 2

    Supabase 테이블 만들기

    회사·구성원·거래처·품목·전표 테이블과 보안 규칙(회사끼리 데이터가 섞이지 않게)을 SQL로 드립니다. 붙여넣고 실행만 하면 됩니다.

    지금
  3. 3

    로그인을 Supabase로 교체

    이메일·비밀번호 가입과 로그인, 비밀번호 재설정 메일. 카카오·구글 로그인은 그다음에 붙입니다.

  4. 4

    데이터 저장을 서버로 교체

    브라우저 저장 대신 Supabase에 저장. 이때부터 다른 PC·직원과 같은 장부를 씁니다.

  5. 5

    정기결제 연결

    토스페이먼츠 등 PG 가입·심사가 필요합니다(사업자등록 필수). 결제 처리는 Supabase 서버 함수에서 합니다.

  6. 6

    속도 개선·도메인

    첫 로딩을 빠르게 하는 빌드 작업과 원하는 주소(예: nonamed.kr) 연결.

1단계 · GitHub Pages에 올리기

  1. 프로젝트 파일 받기

    채팅의 다운로드 카드에서 zip을 받아 압축을 풉니다.

  2. 저장소 만들기

    github.com/new 에서 Repository name에 nonamed 입력, Public 선택 후 Create repository.

  3. 파일 올리기

    새 저장소 화면의 uploading an existing file 링크를 누르고, 압축 푼 폴더 안의 파일을 전부 끌어다 놓습니다. uploads 폴더는 빼도 됩니다. 아래 Commit changes.

  4. Pages 켜기

    저장소 Settings › Pages 에서 Source를 Deploy from a branch, Branch를 main / (root)로 두고 Save.

  5. 접속 확인

    1~2분 뒤 https://(내 GitHub 아이디).github.io/nonamed/ 로 들어가면 로그인 화면이 나옵니다. 주소를 알려주시면 다음 단계로 넘어갑니다.

2단계 · Supabase 테이블 만들기

  1. 새 프로젝트 만들기

    supabase.com/dashboard › New project. 이름 nonamed, Region은 Northeast Asia (Seoul), DB 비밀번호는 따로 적어 두세요.

  2. SQL 실행

    왼쪽 SQL Editor › New query 에 프로젝트 파일의 supabase/schema.sql 내용을 전부 붙여넣고 Run. 아래에 Success. No rows returned가 나오면 됩니다.

  3. 확인

    왼쪽 Table Editor에 companies · members · profiles · records · settings 5개가 보이고, 각 표 옆에 자물쇠(RLS)가 켜져 있으면 성공입니다.

  4. 이메일 로그인 설정

    Authentication › Sign In / Providers › Email 이 켜져 있는지 확인. 테스트 중에는 Confirm email을 꺼 두면 가입 즉시 로그인됩니다. Authentication › URL Configuration의 Site URL에 1단계 주소(https://아이디.github.io/nonamed/)를 넣습니다.

  5. 키 2개 넣기

    Project Settings › API에서 Project URL과 anon public 키를 복사해, 프로젝트의 supabase-config.js에 붙여넣고 GitHub에 다시 올립니다. 이 두 값은 채팅에 붙여 주셔도 됩니다.

표 구성 요약. 회사(초대코드·7일 체험·결제 상태), 구성원(권한·메뉴별 권한), 업무 데이터(거래처·품목·매입·매출·조정·입출금·세금·활동을 한 표에 종류별로), 화면설정. 보안 규칙으로 같은 회사 구성원만 읽고, 조회전용이 아니면서 체험 중이거나 결제된 회사만 쓸 수 있습니다. 결제 상태는 화면에서 바꿀 수 없고 5단계 서버 함수만 기록합니다.
코드가 공개됩니다. 무료 계정의 GitHub Pages는 Public 저장소만 됩니다. 화면 코드가 보일 뿐 고객 데이터는 아닙니다. 코드를 숨기고 싶으면 Cloudflare Pages나 Netlify(비공개 저장소 무료)로 옮기면 되고, 방법은 같습니다.
Supabase 키 관련. 2단계에서 쓰는 anon 키는 원래 공개용이라 화면 코드에 들어가도 됩니다. 실제 보호는 테이블 보안 규칙(RLS)이 합니다. service_role 키는 절대 화면 코드나 채팅에 붙이지 마세요.
